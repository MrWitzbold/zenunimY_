# late-again.exe

*A Flask app for tracking student tardiness, ranking the damage, and attempting to predict future lateness with a homemade neural network.*

This project started with a practical question — “who has been late, and by how much?” — and then escalated into “what if we made a neural network do it?”

The result is part school-admin utility, part machine-learning experiment, and part cautionary tale about giving a very large matrix a job before teaching it what the job is.

## What it does

### 🕒 Records tardiness
The Flask app accepts a student's name, grade, date, and minutes late, then appends the record to `late_days.txt`.

Records are stored as semicolon-separated values:

```text
name;grade;date;minutes;late_index
```

Names are lowercased and normalized with `unidecode`, so accented characters are converted to their unaccented equivalents.

### 🔎 Looks up a student's history
Searches the log for a matching name and grade, then displays the recorded dates and minutes late.

### 🏆 Builds rankings
Two endpoints produce rankings from the log:

- **Frequency ranking** — students with the most recorded tardiness entries first.
- **Minutes ranking** — students with the most accumulated minutes late first.

### 🧠 Experiments with prediction
The `/train` and `/predict_days` routes attempt to train and run a homemade, fully connected neural network. The app saves its state in `weights.txt` and `neurons.txt`, then uses student and date-related values as inputs.

This is an experiment, **not a validated predictive model**. The code currently has significant issues in its training logic, so predictions should not be treated as meaningful or used to make decisions about students.

## The tech stack

- Python
- Flask
- `Unidecode`
- Python's built-in `random`, `math`, `time`, and filesystem utilities
- A plain-text file acting as the database
- A neural network implemented manually, with enthusiasm exceeding its current mathematical supervision

## Getting started

### 1. Install Python

Use a supported Python 3 version.

### 2. Install dependencies

```bash
python -m pip install Flask Unidecode
```

### 3. Check the template

The app expects a `templates/index.html` file containing the form fields used by the routes. That template is not included in this source file, so the interface will need it to render.

### 4. Prepare the data file

Create an empty `late_days.txt` in the project directory before using the app. The current routes open this file directly and do not create it automatically.

### 5. Run it

```bash
python main.py
```

The app starts on port `5000`.

> **Safety note:** the current code runs with `debug=True` and binds to `0.0.0.0`. Keep it on a trusted development machine/network only. Do not expose this version to the public internet.

The text files are runtime data, not source code. They may contain sensitive student information or model state, so they should not be committed to a public repository.

## Known gremlins

This is a prototype, and the source has several important limitations:

- **Plain-text storage:** student records are written directly to a local file, with no database, authentication, access controls, or robust validation.
- **Fragile matching:** lookups use substring matching for names, which can match unintended people.
- **HTML output:** names and other form values are interpolated into HTML strings. User input should be escaped rather than inserted directly into HTML.
- **File handling:** files are opened directly in several routes; missing files, malformed rows, or unexpected values can cause errors.
- **Ranking inconsistencies:** the frequency and minutes rankings count entries differently, and the stored `late_index` is not handled consistently across the code.
- **The neural network is not ready:** the training route does not implement a correct backpropagation procedure. Its weight-update code updates a single indexed weight rather than correctly calculating gradients for the network.
- **Prediction assumptions:** the prediction route hard-codes a school-year calendar and year, and extracts values from decimal string representations. That is brittle and does not establish predictive accuracy.
- **Large memory footprint:** the initial network allocates a dense matrix with millions of weights. This can consume substantial memory and make training slow.
- **Debug mode:** Flask's debugger must not be exposed to untrusted users.

## Student privacy matters

Tardiness logs are student records. Before using this for real school data, add appropriate authentication and authorization, validate and escape all input/output, protect stored files, define retention rules, and follow the applicable school and data-protection policies (including LGPD requirements where applicable).

For a public demo, use synthetic names and fake records only.

## Ideas for a future version

- Replace the text file with SQLite or another properly managed database.
- Use exact, normalized student identifiers instead of substring name matching.
- Validate dates, grades, and non-negative minute counts.
- Escape output or render structured data safely through Jinja templates.
- Add authentication, role-based access, and audit logging.
- Separate the record-keeping features from the machine-learning experiment.
- If prediction is still the goal, start with a clear target, a train/validation split, a baseline model, appropriate evaluation metrics, and a tested learning algorithm.
- Add tests for logging, lookups, rankings, malformed rows, and prediction behavior.

## The honest status

**The tardiness log and rankings are the practical core. The neural network is experimental and currently needs substantial debugging before it can be trusted.**

This repository is best treated as a learning project and a snapshot of a very specific development philosophy:

> First, make it work. Then make it make sense. Then maybe let it near production.
